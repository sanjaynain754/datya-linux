# Datya Linux v0.1.4

Datya Linux v0.1.4 is an engineering development release focused on making the v0.1.3 foundation more reproducible, presentable, and useful as a security-workbench base. It preserves the v0.1.3 tag and release assets; this release is built from the post-v0.1.3 `main` history.

## What changed

The release includes the verified RustScan 2.4.1 integration for amd64 and arm64 metadata, an opt-in `security-lab` network pack entry, the `rustscan-network-scan` daemon route, dry-run-by-default behavior, explicit authorized scope, typed operator confirmation, bounded execution, and local hash-chain evidence. RustScan is not started automatically and is not chained to Nmap.

The repository now includes the complete GPL-3.0 license text, a responsible-disclosure policy, promotion-ready README badges and screenshots, and verified maintainer contact information. Debian Trixie package naming is normalized to `bind9-dnsutils`, and the package manifest contains the corresponding verified record.

The release also corrects the CI assertions for the actual Calamares live-image installer path, keeps tracked Calamares and security-hook templates across clean ISO rebuilds, and makes the Guardian kernel-module fallback explicit when the generic Debian kernel does not export the required tracepoints. In that case the userspace collector remains the supported evidence path.

## Validation status

The latest GitHub Actions run passes Rust formatting, workspace tests, Clippy, the C++ control-daemon build, shell and Python policy checks, package-manifest checks, Calamares validation, source-policy checks, and private-signing-material checks. The test suite currently reports 35 passing tests and one environment-dependent Bubblewrap skip.

The v0.1.4 Debian Trixie amd64 ISO was built locally from the release candidate source and verified as an ISO-hybrid image with El Torito BIOS metadata. The release-bundle checksum is `5bac95dea3faf33ac0456015fad384a029a83abf43ce0a56573cd8b57c1acb71`. Its embedded build metadata reports `DATYA_VERSION=0.1.4`, and the SquashFS payload contains RustScan, Calamares, and the visible Datya policy markers. The ISO is not considered publicly published until the final tag and GitHub release asset are verified.

## Hardware target

The primary target remains modern 64-bit Intel and AMD desktops, workstations, laptops, and x86_64 virtual machines. A practical minimum is 4 GiB RAM, 4 GiB swap, approximately 30 GiB free storage, and a 16 GiB USB drive. Eight GiB RAM and 60 GiB storage are recommended for the full security-workbench experience.

Arm64 package metadata is present, but a v0.1.4 arm64 ISO and board-specific validation are not yet complete. Apple Silicon, 32-bit PCs, phones, tablets, and model-specific Wi-Fi, GPU, suspend, fingerprint, encryption, and recovery behavior remain unverified unless separately documented by a hardware report.

## Security status and limitations

The project retains dry-run defaults, explicit scope, confirmation gates, local-only defaults, sandbox profiles, signed-update design goals, and no hidden telemetry. The v0.1.4 engineering artifact is not a claim that Secure Boot signing, physical-device installation, encrypted installation, recovery, or every hardware combination has been validated. Test signing scripts are for controlled development use and must not be confused with a production key hierarchy.

## Upgrade guidance

Keep the v0.1.3 ISO and checksum available as a rollback artifact. Test v0.1.4 first in a disposable VM or on a spare disk. Verify the downloaded checksum before booting, and do not run RustScan or any network tool against systems without explicit authorization.
